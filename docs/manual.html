GigaChanie

개요

GigaChanie는 상용 API 없이 로컬 또는 자가 호스팅한 오픈 모델 위에서 도는 코딩 에이전트입니다. 에이전트 루프가 도구를 호출해 코드베이스를 조사하고 수정하며, 모든 쓰기·실행·네트워크 동작은 승인 정책을 통과합니다.

doctor

OS·CPU·RAM·GPU를 감지해 이 장비에서 돌릴 수 있는 모델을 추천합니다.

agent / chat

단발 실행과 대화형 REPL. 읽기 도구는 항상, 쓰기·웹 도구는 플래그로 켭니다.

apply_edit

SEARCH/REPLACE 방식 편집. 정확→공백무시→들여쓰기유연 순으로 매칭합니다.

AGENTS.md

프로젝트 규칙을 매 세션 자동으로 읽습니다. giga init이 초안을 만듭니다.

설치

Python 3.11 이상이 필요합니다. 로컬 모델을 쓰려면 별도로 Ollama를 설치하세요.

# 저장소에서 편집 가능 모드로 설치
python -m pip install -e ".[dev]"

# 확인
giga --version
giga --help

설치하면 giga 명령이 생깁니다. python -m gigachanie 로도 실행됩니다.

빠른 시작

장비 진단 → 모델 선택(자동 다운로드) → 대화 시작.

giga doctor                              # 장비에 맞는 모델 추천
giga model use qwen3-coder-30b-a3b-instruct # 선택 + 가중치 자동 다운로드
giga ping                                # 백엔드 연결 확인

# 읽기 전용으로 코드베이스 질문
giga agent "이 프로젝트 구조를 설명해줘"

# 편집까지 (대화형, 각 변경 승인)
giga chat -w

참고 실제 모델 호출에는 Ollama 실행과 모델 다운로드가 필요합니다. giga model use는 모델이 없으면 자동으로 받습니다(대화형에서는 먼저 확인).

giga doctor

OS·CPU·RAM·GPU(VRAM)와 사용 가능한 로컬 백엔드를 감지하고, 모델별로 확보 가능한 컨텍스트 길이를 KV 캐시 공식으로 계산해 적합도·속도와 함께 표로 보여줍니다.

giga doctor [--all] [--json] [--top N]
옵션설명
--all, -a실행 불가한 모델도 이유와 함께 표시
--json결과를 JSON으로 출력 (스크립트용)
--top, -n표시할 추천 모델 수 (기본 8)

메모리 예산은 통합 메모리(Apple Silicon)·VRAM(외장 GPU)·시스템 RAM(CPU 전용)을 구분해 산출합니다.

giga model

모델 후보 조회, 선택, 다운로드. 선택 정보는 ~/.config/gigachanie/config.yaml에 저장됩니다.

giga model list [--family NAME] [--kind KIND] [--fit]

레지스트리의 모델 25종을 표로 표시하고, 이 장비에서의 적합도를 함께 보여줍니다.

--family, -f계열 필터: qwen, llama, deepseek, mistral …
--kind, -k종류 필터: coder, general, reasoning
--fit실행 가능한 모델만 표시
giga model use <ID> [--backend B] [--base-url URL] [--quant Q] [--context N] [--pull] [--no-pull]

사용할 모델을 선택합니다. ollama 백엔드에서 모델이 없으면 가중치를 자동 다운로드합니다 (대화형 터미널에서는 먼저 확인, 비대화 환경에서는 바로).

--backend, -bollama 또는 openai_compat
--base-urlopenai_compat 엔드포인트 (예: http://localhost:8000/v1)
--quant, -q양자화 이름 (예: q4_K_M)
--context, -c컨텍스트 길이(토큰)
--pull, -p다운로드 실패 시 오류로 종료 (강제)
--no-pull받지 않고 설정만 저장
giga model show

현재 선택된 모델·백엔드·설정 파일 경로를 표시합니다.

giga model pull [ID]

선택된(또는 지정한) 모델을 ollama pull로 내려받습니다.

giga ping · giga ask

giga ping

선택된 백엔드/모델에 연결이 되는지, 모델이 로드 가능한지 확인합니다.

giga ask "질문" [--system S] [--temperature T] [--max-tokens N] [--no-stream]

도구 없이 모델에 한 번 질문하고 답을 스트리밍합니다. 질문을 생략하면 표준입력에서 읽습니다 (cat prompt.txt | giga ask).

--system, -s시스템 프롬프트
--temperature, -t샘플링 온도 (기본 0.0)
--max-tokens, -m최대 출력 토큰 (0 = 제한 없음)
--no-stream스트리밍 비활성화

giga agent

에이전트 루프를 한 번 실행합니다. 읽기 도구는 항상 켜져 있고, --write로 편집·셸을, --web로 웹 도구를 추가합니다.

giga agent "작업" [-C DIR] [-w] [--web] [--mode M] [--yolo] [--max-steps N] [-t T] [--no-context]
--root, -C작업 루트 디렉터리 (기본 현재 위치)
--write, -wwrite_file, apply_edit, run_shell 활성화
--webweb_search, web_fetch 활성화
--mode승인 모드: suggest · auto-edit · full-auto
--yolofull-auto + --write. 확인 없이 전부 실행 주의
--max-steps최대 반복 스텝 (기본 20)
--temperature, -t샘플링 온도
--no-contextAGENTS.md 등 프로젝트 컨텍스트를 읽지 않음
--no-map저장소 심볼 맵을 컨텍스트에 넣지 않음
--compact-at이 토큰 수 초과 시 대화 자동 압축 (0 = 컨텍스트의 70%)
 
giga agent -w --mode auto-edit "모든 함수에 타입 힌트를 추가해줘"
giga agent --web "httpx 최신 버전 마이그레이션 가이드를 찾아서 적용해줘"
giga agent "이 @src/loop/agent.py 의 반복 가드 로직을 설명해줘"

giga chat

대화 맥락을 유지하는 REPL. 입력 히스토리가 저장되고, 슬래시 명령으로 모델·모드·도구를 즉석에서 바꿉니다.

giga chat [-C DIR] [-w] [--web] [--mode M] [--max-steps N] [-t T] [--no-context]

옵션은 giga agent와 같습니다. 세션 중 슬래시 명령:

명령동작
/help명령 목록
/tools현재 등록된 도구
/model [ID]현재 모델 표시 / 변경 (맥락 유지)
/mode <모드>승인 모드 변경
/write on|off쓰기·실행 도구 토글
/web on|off웹 도구 토글
/remember <내용>장기 메모리에 저장
/memory장기 메모리 목록
/compact지금까지 대화를 요약해 압축
/steps <N>최대 스텝 변경
/clear대화 맥락 초기화 (설정 유지)
/info현재 세션 상태
/exit, /quit종료 (Ctrl-D 도 가능)

giga init

리포를 훑어 언어 구성·빌드/테스트/린트 명령·디렉터리·git 원격을 감지하고 AGENTS.md 초안을 만듭니다.

giga init [-C DIR] [--force] [--show]
--root, -C대상 디렉터리
--force, -f기존 AGENTS.md 덮어쓰기
--show파일로 쓰지 않고 출력만

감지 대상: pyproject.toml, package.json, Cargo.toml, go.mod, Makefile. 생성 후 반드시 내용을 검토하세요.

giga map

소스 파일에서 심볼(클래스·함수·상수)을 추출하고, 파일 간 참조 그래프에 PageRank 를 돌려 중요한 파일부터 개요를 만듭니다. 파이썬은 ast, 그 외 언어는 정규식으로 처리합니다(tree-sitter 미사용). agent·chat은 이 맵을 시스템 프롬프트에 자동으로 넣습니다.

giga map [-C DIR] [--budget N] [--files N] [--json]
--budget맵 텍스트 문자 예산 (기본 8000)
--files스캔할 최대 파일 수 (기본 400)
--json파일별 심볼을 JSON 으로 출력

giga memory

이후 세션에서도 쓸 정보(프로젝트 규칙·결정·맥락)를 <루트>/.agent/memory/에 낱개 마크다운으로 저장합니다. agent·chat은 시작 시 목차를 컨텍스트에 주입하고, 에이전트는 read_memory 도구로 필요한 본문만 가져옵니다.

giga memory add <제목> [-b 본문] [-t 태그] · list · show <slug> · search <쿼리> · rm <slug>
add메모리 추가. -b 생략 시 표준입력에서 본문을 읽음
list저장된 메모리 표
show <slug>본문 출력
search <쿼리>토큰 겹침으로 검색
rm <slug>삭제

회수는 토큰 겹침 점수 기반입니다(임베딩 미사용). 대화 중에는 /remember <내용>, /memory로도 다룰 수 있습니다.

도구

에이전트가 호출하는 도구. 읽기 도구는 기본, 나머지는 플래그로 활성화합니다.

읽기 항상

도구설명
list_dir디렉터리 목록 (빌드 산출물·VCS 디렉터리 제외)
read_file행 번호와 함께 읽기, 행 범위 지정 가능, 200KB 초과 시 잘림
glob패턴으로 파일 찾기 (**/*.py)
grep정규식으로 내용 검색, glob으로 대상 좁히기
read_memory장기 메모리 본문 조회 (slug 또는 query)

쓰기 · 실행 --write / -w

도구설명
write_file파일 전체 쓰기. 승인 시 diff 표시, 내용 동일하면 no-op
apply_edit부분 수정. search를 찾아 replace로 교체. search가 빈 문자열이면 새 파일 생성
run_shell셸 명령 실행 (Windows=PowerShell, 그 외=sh). 타임아웃 최대 600초, 종료코드 반환
save_memory장기 메모리에 저장 (승인 필요)

웹 --web

도구설명
web_search기본 DuckDuckGo(키 불필요). GIGA_SEARCH_URL 설정 시 SearXNG
web_fetchURL → 본문 텍스트 (HTML에서 스크립트·스타일 제거), 20KB 제한

경로 도구는 작업 루트 밖을 벗어날 수 없습니다. 위험한 셸 명령 (rm -rf /, mkfs, fork bomb 등)은 승인 모드와 무관하게 차단됩니다.

승인 모드

쓰기·실행·네트워크 동작은 실행 전에 정책을 통과해야 합니다.

모드파일 편집셸 실행웹 요청
suggest 기본 확인확인 (허용 목록 제외)확인
auto-edit 자동확인 (허용 목록 제외)확인
full-auto 자동자동 (거부 목록 제외)자동
  • 허용 목록 — git status, pytest, ruff 등 안전한 읽기성 명령은 모드와 무관하게 자동 승인.
  • 거부 목록 — 파괴적 명령은 모드와 무관하게 차단.
  • --yolo — full-auto + --write 를 한 번에. 확인 창이 전혀 뜨지 않습니다.
  • 승인 거부는 오류가 아니라 모델에게 피드백으로 전달되어 다른 방법을 찾게 합니다.

컨텍스트 & @참조

프로젝트 컨텍스트 파일

에이전트는 매 세션 프로젝트 규칙을 자동으로 읽습니다. 인식 파일 (우선순위 순):

  • AGENTS.md (권장) → GEMINI.md → CLAUDE.md → .agent/context.md

계층 병합: 전역(~/.config/gigachanie/AGENTS.md) → 프로젝트 루트 → 작업 하위 디렉터리 순서로 합쳐집니다 (총 12KB 상한). --no-context로 끌 수 있습니다.

저장소 심볼 맵

agent·chat은 시작 시 giga map과 같은 맵을 만들어 시스템 프롬프트에 넣습니다. 에이전트가 매번 파일을 더듬지 않고 어디에 무엇이 있는지 알고 시작합니다. --no-map으로 끕니다.

장기 메모리

giga memory로 저장한 항목의 목차가 매 세션 컨텍스트에 들어갑니다 (본문 아님). 에이전트는 관련될 때 read_memory로 본문을 가져오고, save_memory로 새 항목을 남깁니다. --no-context는 프로젝트 컨텍스트와 메모리 목차를 함께 끕니다.

세션 대화 압축

대화 토큰 추정치가 임계값(--compact-at, 기본은 모델 컨텍스트의 70%)을 넘으면 오래된 메시지를 요약 하나로 치환합니다. 시스템 프롬프트와 최근 메시지는 그대로 둡니다. chat에서 /compact로 직접 실행할 수도 있습니다.

@파일 참조

입력에 @경로를 쓰면 해당 파일 내용이 프롬프트에 첨부됩니다. 공백이 있으면 @"경로 이름"처럼 따옴표로 감쌉니다.

설정

필드: model_id, backend, base_url, quant, context.

개발

모든 변경은 테스트·린트·타입체크를 통과해야 합니다.

python -m pytest        # 테스트 (실서버 없이 Mock으로 동작)
ruff check .            # 린트 (line-length 100)
