# 아키텍처

## 큰 그림

코딩 에이전트는 6개 레이어로 구성된다.

| 레이어 | 역할 | 모듈 |
|--------|------|------|
| 1. 모델 서빙 | 오픈모델을 OpenAI 호환 API로 노출 | `serving/` |
| 2. 에이전트 루프 | 프롬프트 → 툴 호출 → 실행 → 결과 피드백 반복 | `loop/` |
| 3. 툴셋 | 파일 읽기/쓰기/편집, 검색, 셸 실행 | `loop/tools.py` |
| 4. 컨텍스트 | repo map, 메모리, 열린 파일 등을 예산 내에서 주입 | `context/` |
| 5. UX 표면 | CLI(현재) → GUI(VS Code 확장 / 독립 앱) | `cli.py`, 이후 별도 |
| 6. 부가 | 오케스트레이션, 세션/체크포인트, 샌드박스, 권한 | `orchestra/`, `safety/` |

## 디렉터리 구조

```
src/gigachanie/
  cli.py                 # 진입점 (typer)
  commands/              # setup · doctor · model · ask/ping · agent · chat · init ·
                         #   map · memory · eval · undo · ps/kill · policy · route · review
                         # _pick.py: 화살표 선택 UI, _agentui.py: 렌더·3지선다 승인

  config.py              # 사용자/프로젝트 모델 설정 로드·병합
  permissions.py         # permissions.yaml 병합 (승인 모드·셸/경로 규칙, 민감정보 가드)
  providers/
    hardware.py          # doctor: OS/CPU/RAM/GPU 감지 + 모델 추천
    model_registry.yaml  # 모델 후보 카탈로그
    registry.py          # 레지스트리 로더·필터
  serving/
    base.py              # Backend 프로토콜 + Message/ToolCall/ToolSpec/ChatResponse
    toolcall.py          # 네이티브/프롬프트형 툴콜 파싱, 균형괄호 JSON 복구
    ollama.py            # /api/chat (num_ctx, keep_alive)
    openai_compat.py     # llama.cpp / MLX / vLLM / 호스팅 API 공용, SSE 스트리밍
    factory.py           # Config(+orchestra.yaml) → Backend / RouterBackend
    ollama_setup.py      # Ollama 자동 설치(winget/brew/install.sh) + 데몬 확인
  context/
    project_file.py      # AGENTS.md/GEMINI.md/CLAUDE.md 계층 로더
    refs.py              # 입력의 @경로 → 파일 내용 확장
    symbols.py           # 심볼 추출 (파이썬 ast + 정규식 폴백)
    repo_map.py          # 파일 참조 그래프 PageRank 랭킹 + 예산 렌더
    memory.py            # 장기 메모리 저장소 (.agent/memory, INDEX.md, 토큰겹침 회수)
    budget.py            # (예정) provider별 토큰 예산 배분
  loop/
    agent.py             # 툴 루프 + AgentEvent 스트림 + 반복 가드
    tools.py             # Tool 프로토콜, ToolRegistry, ToolContext(경로 샌드박스)
    builtin_tools.py     # 읽기 전용: list_dir/read_file/glob/grep/ask_user
    memory_tools.py      # read_memory(읽기) / save_memory(쓰기)
    compact.py           # 세션 대화 압축 (오래된 메시지 → 요약 1개)
    checkpoint.py        # 편집 직전 파일 스냅샷 + giga undo
    write_tools.py       # write_file/run_shell/apply_edit (승인 정책 연동)
    proc_tools.py        # run_background/tail_logs/wait_for_log/stop_process/list_processes
    procman.py           # ProcessManager: 분리 실행 + 로그 파일 + 레지스트리
    web_tools.py         # web_search(DDG/SearXNG) / web_fetch (opt-in, network 승인)
    approval.py          # ApprovalPolicy: suggest/auto-edit/full-auto + 셸 allow/deny + network
    prompt.py            # 기본 시스템 프롬프트
    edit.py              # SEARCH/REPLACE 파서 + 단계적 매칭(정확→공백무시→들여쓰기유연)
  orchestra/
    router.py            # 작업 분류(TaskKind) → orchestra.yaml 매핑 → RouterBackend
    pipeline.py          # review_diff: draft 편집 → review 모델이 diff 검토
    ensemble.py          # (예정) 병렬 실행 + 투표/판정
  safety/
    permissions.py       # 승인 모드, 화이트리스트
    sandbox.py           # 셸 실행 격리
  eval/
    harness.py           # 태스크 로드·복제·실행·판정, EvalReport
    tasks/<name>/         # task.yaml + repo/ (내장 3종)
```

## 설정 우선순위

`기본값` < `~/.config/gigachanie/config.yaml` < `프로젝트/.agent/config.yaml` < `환경변수` < `CLI 플래그`

## 컨텍스트 예산 (예: 32k 컨텍스트 모델)

| provider | 예산 | 비고 |
|----------|------|------|
| 시스템 프롬프트 + 툴 정의 | ~2k | 고정 |
| repo map | ~6k | 심볼 랭킹 상위 |
| 메모리(INDEX + 회수분) | ~2k | 임베딩 검색 |
| 열린/참조 파일 | ~10k | 요청에 따라 |
| 대화 이력 | 나머지 | 길어지면 요약 압축 |

## 편집 전략

소형 오픈모델은 대형 unified diff 생성이 불안정하므로 **SEARCH/REPLACE 블록**을 기본으로 한다.

````
파일: src/foo.py
<<<<<<< SEARCH
    return a + b
=======
    return a + b + c
>>>>>>> REPLACE
````

적용 실패 시 실패 사유를 모델에 되돌려 재시도한다. diff 모드는 대형 모델 사용 시 옵션으로 제공.
